DLRM on Ascend 950DT — 加大 batch 的扩展曲线 + TASK_QUEUE 开关（8 die, 150 步/次, warmup 20）

配置：统一表 + EC + index dedup（A2 及以上）；A1 用 EBC 更优
口径：step = forward/backward/step；端到端 = step + host 取数（已把 log1p/dtype 固化到加载期）
说明：节点为多租户，同一配置不同批次波动 ±8~12%，故下表给原始值与中位

一、扩展曲线（每卡本地 batch → 端到端吞吐）
  global 2,048   (256/卡)   step 6.70  prep 0.67  端到端 7.36 ms  =  278,111 sps  = A100-A1 135.8%
  global 16,384  (2,048/卡) step 14.70 prep 1.53  端到端 16.23 ms = 1,009,000 sps = A100-A2 109.0%
  global 32,768  (4,096/卡) step 21.30 prep 2.99  端到端 24.29 ms = 1,349,000 sps
  global 65,536  (8,192/卡) step 29.52 prep 7.24  端到端 36.76 ms = 1,783,000 sps
  global 131,072 (16,384/卡) step 56.60 prep 5.70 端到端 62.30 ms = 2,104,000 sps = A100-A4 176.8%

  A100 官方锚：A1 204,800 / A2 925,696 / A4 1,190,128 sps
  ⚠️ A4 对照不完全等价：A100 的 A4 档用 DCN v2 交互，本实现只有 dot（更省算力），
     故 176.8% 不是同模型对比，只能作为规模参考。

二、A4 档（global 131,072）四次原始值
  step median: 54.49 / 54.97 / 56.89 / 56.60 ms（吞吐 2,486,643 / 2,425,191 / 2,253,076 / 2,240,980 sps）
  中位 2,339,134 sps = A100-A4 的 196.5%（纯 step 口径）
  prep 5.2~6.2 ms（固化前为 12.5 ms）

三、TASK_QUEUE_ENABLE 开关（A2 档，交错 3 轮抵消漂移）
  默认      : 1,091,524 / 1,081,909 / 967,368  -> 中位 1,081,909
  =2        : 1,156,461 / 1,110,798 / 1,110,617 -> 中位 1,110,798（+2.7%，三轮方向一致，均值 +7%）
  =1        : 1,006,712（单次，介于两者之间）
  A4 档 =2  : 2,381,720 / 2,389,874 -> 中位 2,385,797（比默认 -2.9%）

  结论：=2 在 A2 有小幅正收益、在 A4 略负；不设全局默认，按档选。

四、取数开销优化（有效）
  原实现每步做 log1p(astype(f64)) + astype(i64)：
    131k 档 prep 12.46 ms -> 固化 dtype 后 5.2~6.2 ms（-50%+）
    16k 档 prep 1.46 ms -> 1.10~1.53 ms
  改法：加载期一次性 log1p 并转 float32/int64，训练期只做切片拷贝。

五、AUC（150 步链路值，非收敛精度）
  16k 档 0.7404~0.7410；32k 0.7339；64k 0.7367；131k 0.7439

六、结论
  1. 950 的优势在大 batch 才体现：固定开销被摊薄后，A4 档达到 A100 的 196.5%（step）/ 176.8%（端到端）。
  2. 小 batch（A1）受单步固定开销限制，只能到 136%。
  3. 剩余可动项集中在 wait/空隙（阶段 2 实测 64% wall），需要通信与计算重叠、或减少 collective 发射次数。
