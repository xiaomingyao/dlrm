# DLRM 在昇腾 950DT 上的性能报告：与 8×A100 对比 · 诊断 · 优化

本报告合并原「优化报告 v1/v2」与「性能诊断报告」，共 11 章。

- **硬件**：8 die Ascend950DT（单 die HBM 96 GiB，UB 互联）· CANN 9.1.0 · 驱动/固件 25.1.rc2 / 7.0.9.100.203
- **模型**：bottom MLP 13→512→256→128 + 27×27 dot 交互 + top MLP 857→1024→1024→512→256→1 + 26 张稀疏表（HKV 动态表）
- **数据**：Criteo 1TB 切片（day0–6；训练 22,184,476 行 / 测试 2,295,467 行），MLPerf 词表 268,435,456 行
- **对照**：8×A100 40GB（同数据、同 dot 交互、同每卡本地 batch；A4 档 A100 侧为 DCN v2）

## 1. 结论摘要

| 档 | 950 sps | A100 sps | 对 A100 |
|---|---:|---:|---:|
| A1（global 2,048） | 275,000 | 204,800 | **134.3%** |
| A2（global 16,384） | 1,015,600 | 925,696 | **109.7%** |
| A4¹（global 131,072） | 2,104,000 | 1,190,128 | **176.8%** |

¹ A100-A4 用 DCN v2，本实现只有 dot（算力需求更低），该档非同模型对比，仅作规模参考。

| 判断 | 依据 |
|---|---|
| 已超过同档 A100 | A1 134.3%、A2 109.7%（端到端，含 host 取数），同数据、同 8 卡、同 dot、同每卡本地 batch |
| 大 batch 是 950 的主场 | 固定开销 8.33 ms + 0.361 µs/样本；16,384→131,072 每样本成本 0.897→0.432 µs，吞吐 2.08× |
| 阶段一 2× 未达成 | A1 需 ≤5.00 ms（当前 7.44）、A2 需 ≤8.85 ms（当前 16.13）；剩余可动项上限合计 10–11 ms |
| 瓶颈不是算力而是「等」 | Cube 在矩阵乘内忙 91.3%，但矩阵乘只占步时 6.8%/13.9%；wait+空隙 64%/44%，通信 25% |
| 整机占用天然偏低 | 训练对齐采样 AICore 4.84%（峰值 17%），与理论占空 6.8%×91.3%≈6.2% 一致 |

## 2. 评测条件与口径

| 项 | 说明 |
|---|---|
| 并行方式 | 8 die 单机 DMP（模型并行 + 数据并行），每卡本地 batch = global/8，两侧一致 |
| 表放置 | 26 表合 1 张统一表（id 区间互不重叠），行数 268,435,456，按行切分到 8 die |
| 优化器 | 稠密 SGD；稀疏 Adagrad（row-wise） |
| 步时 | forward + backward + optimizer.step；起点为「拿到本步数据之后」，每步 synchronize 后计时 |
| **端到端** | **步时 + host 取数**（numpy 切片 → tensor → H2D）。A100 官方口径含取数，故对外一律给端到端 |
| 统计 | 多轮取 median，稳态剔除前 20 步；单次值只作方向判断 |
| 噪声 | 多租户节点，同配置不同批次波动 ±8~12%；A/B 一律交错多轮 |
| profiling | 阶段 0/1 用 msprof（含 AICPU/SDMA）；阶段 2/3 用 torch_npu.profiler（该配置下 msprof 段错误）；扰动 1.19–1.30×，只看占比 |
| 换算 | 每样本训练算力 17.1 MFLOPs；稀疏访存 15.8 KB/样本 |

## 3. 与 8×A100 的对比

### 3.1 三档总表（端到端口径）

| 档 | global | 每卡 | A100 ms | A100 sps | 950 ms | 950 sps | 占比 |
|---|---:|---:|---:|---:|---:|---:|---:|
| A1 | 2,048 | 256 | 10.00 | 204,800 | 7.44 | 275,000 | **134.3%** |
| A2 | 16,384 | 2,048 | 17.70 | 925,696 | 16.13 | 1,015,600 | **109.7%** |
| A4¹ | 131,072 | 16,384 | 110.13 | 1,190,128 | 62.30 | 2,104,000 | **176.8%** |

A1 用「统一表 + EBC」，A2/A4 用「统一表 + EC + dedup」，按档选配置（§4）。
A1 两次独立测量：150 步 6.70+0.67=7.36 ms（135.8%）、200 步 6.92+0.52=7.44 ms（134.3%），属步时抖动；对外取保守的 7.44 ms。

## 4. 优化账本（O1–O18）

| 编号 | 优化项 | 结论 | 实测 / 依据 |
|---|---|---|---|
| O6 | **统一表**（26→1，rows=268,435,456） | 有效 | A2 40.27→20.34 ms；查表反向 24×615 µs→1×3413 µs；task 536→173 |
| O7b | **EC + index dedup** | 大 batch 有效 | A2 20.34→16.31 ms（n=3）；EC 无 dedup 62.41 ms ⇒ 收益来自 dedup |
| O12 | 取数固化（加载期 log1p + dtype） | 有效 | 131k 档 prep 12.5→5.70 ms |
| O14 | 加大 batch（16,384→131,072） | 有效 | 端到端 16.23→62.30 ms，吞吐 1.01→2.10 M sps（2.08×） |
| O13 | TASK_QUEUE_ENABLE=2 | 按档 | A2 +2.7%；A4 两批 +2.0%/−2.9%，方向不稳 |
| O7c | 局部图捕获（只稠密段） | 备选 | 上限约 1.3 ms，暂不做 |
| O11 | 表行数去 2 的幂 | 待测 | 可省 32 GiB 表内存 + 4 GiB/die；`--unified-align batch` 已实现未上机 |
| O18 | 减少 all2all 实例（计数对齐） | 观察 | A4 约 100 个形状特化 kernel 名，alltoall 18.5 ms/步；上限 4–6 ms |
| O1 | 逐步同步节奏（1/2/4/8/50） | 无效 | 差 <1.2 ms；sync=50 +49% |
| O2 | dist-type roundrobin | 否决 | A1 +8.6%、A2 +1.8%（n=3 推翻单次 −3.7%） |
| O3 | frozen-data | 仅诊断 | 取数上限探针，不作方案 |
| O4 | hbm-gb 加大 | 否决 | 无收益 |
| O5 | batch 32,768 对照 A100 | 不可比 | A100 无对应档 |
| O7a | 整步 NPUGraph 捕获 | 不可行 | 稀疏路径含 H2D → 107030 |
| O8 | 合并 collective | 降级 | 统一表后通信并集仅 1.69 ms |
| O15 | all2all 载荷 bf16 | 变差 | 64k 档 29.52→34.23 ms（+16%） |
| O16 | HCCL_OP_EXPANSION_MODE=AIV | 无效 | A4 57.78→58.52 ms（噪声内） |
| O17 | HCCL_BUFFSIZE=1024 | 显著变差 | A4 57.78→67.29 ms（+16%） |

有效项 4 个；按档组合：**A1 = 统一表 + EBC**，**A2/A4 = 统一表 + EC + dedup**。

## 6. 硬件利用率

### 6.1 算子级

| 指标 | A2 | A4 | 含义 |
|---|---:|---:|---|
| MatMulV3 cube_utilization | **91.3%**（峰 99.5%） | ≈91% | 算子接近理论上限 |
| aic_mac_ratio | 0.77 | ≈0.77 | MAC 占 Cube 时间 77% |
| 矩阵乘占窗口 | 6.8% | 13.9% | 稠密侧不是主要开销 |
| 通信占窗口 | 25% | 25% | all2all 为主 |
| wait + 空隙 | **64%** | **44%** | 等前驱/等对端/下发断档 |

### 6.2 整机级（宿主 npu-smi）

| 采样方式 | AICore | 峰值 | 说明 |
|---|---:|---:|---|
| 训练对齐（等 ep0 step 后采，0.5 s 间隔） | **4.84%** | 17% | 与理论占空 6.2% 一致 |
| 早期采样（启动后 35 s 起采 30 s） | 2.9% | 14% | **作废**：窗口覆盖加载与收尾 |

AIVector 0.6%（峰值 3%）、AICPU 0.1%、HBM 带宽 0%（= 峰值 0.27%）。

### 6.3 HBM 带宽为什么显示 0%

| 探针 | 实测带宽 | npu-smi HBM | npu-smi AICore |
|---|---:|---:|---:|
| copy_ 2 GiB × 11,000 次（14.26 s） | 3,313 GB/s | 76–77% | 99% |
| add 2 GiB（out=） | 4,738 GB/s | — | — |

反推 100% ≈ 4,300 GB/s/die。DLRM 每 die 每步约 173 MB（稀疏 2.4 + 权重 41 + 激活 130）/ 15 ms ≈ **11.5 GB/s = 0.27%** ⇒ 整数百分比显示 0%。带宽不是约束。

### 6.4 表规模与内存

| 项 | 值 | 说明 |
|---|---:|---|
| 行数（对齐后 / 原始） | 268,435,456 / 204,222,464 | 对齐白占 32 GiB（31.4%），4 GiB/die |
| 表本体（128 维 fp32） | 128 GiB → 16 GiB/die | 8 die 行切分 |
| Adagrad 状态（16 float/行） | 16 GiB → 2 GiB/die | row-wise |
| embedding 单 die 合计 | **≈18 GiB / 96 GiB（19%）** | 能上 131,072 的前提 |

## 7. 归因

### 7.1 已坐实

- 查表不再是瓶颈：24 次（15.05 ms）→ 1 次（0.081 ms）。
- 通信稳定 25%：每步 5 次 all2all（@A4 ≈18.5 ms）+ 6 次 HcclLaunch 1.23 ms 纯发射。
- wait + 空隙最大：A2 64%、A4 44%。
- 算子无空间：Cube 91.3%、MAC 比 0.77。
- 带宽无空间：0.27% 占用；bf16 化更慢（O15 +16%）。

### 7.2 推测（未坐实）

- 【推测】A4 档 all2all 约 100 个形状特化 kernel 名，说明分块随 dedup 后 id 数变化，可能触发重编译/重下发；计数对齐可减 4–6 ms。
- 【推测】各 rank dedup 后 id 数不均衡导致 all2all straggler，是 wait 来源之一；未取逐 rank 分布。

## 8. 剩余空间与下一步

| 可动项 | 上限 | 当前 | 前置条件 |
|---|---:|---|---|
| 通信与计算重叠 | ~5 ms | 已试 −4%（单次） | 需 n=3；A4 无效 |
| 减少 all2all 实例 | 4–6 ms | 18.5 ms（A4） | 改 dynamic_emb |
| rank 间负载均衡 | 2–4 ms | 未知 | 先取逐 rank 计数 |
| 合并 collective | ~1.2 ms | 1.23 ms | 收益已很小 |
| 算子优化 | ≈0 | Cube 91.3% | — |

合计乐观 10–11 ms（A2 端到端）≈1.5× 当前、1.6–1.7× A100，仍不到 2×（8.85 ms）。结构性原因：每卡每步仅 2,048 行，固定开销 8.33 ms 占 51%。

## 9. 已验证无效

| 项 | 结论 | 实测 |
|---|---|---|
| 逐步同步节奏 | 无效 | <1.2 ms；sync=50 +49% |
| dist-type roundrobin | 无效 | A1 +8.6%、A2 +1.8% |
| all2all bf16 | 变差 | +16% |
| HCCL_OP_EXPANSION_MODE=AIV | 无效 | 噪声内 |
| HCCL_BUFFSIZE=1024 | 变差 | +16% |
| 整步 NPUGraph 捕获 | 不可行 | 107030 |
| TASK_QUEUE_ENABLE=2 | 按档 | A2 +2.7%；A4 不稳 |
