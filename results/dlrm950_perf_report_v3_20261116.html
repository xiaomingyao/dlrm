DLRM 在昇腾 950DT 上的性能报告：与 8×A100 对比 · 诊断 · 优化

本报告合并原「优化报告 v1/v2」与「性能诊断报告」，共 10 章：结论 → 口径 → 对比 → 优化账本 → 时间分解 → 利用率 → 归因 → 剩余空间 → 无效清单 → 复现。
硬件：8 die Ascend950DT（单 die HBM 96 GiB，UB 互联）· CANN 9.1.0 · 驱动/固件 25.1.rc2 / 7.0.9.100.203
模型：bottom MLP 13→512→256→128 + 27×27 dot 交互 + top MLP 857→1024→1024→512→256→1 + 26 张稀疏表（HKV 动态表）
数据：Criteo 1TB 切片（day0–6；训练 22,184,476 行 / 测试 2,295,467 行），MLPerf 词表 26 特征合计 268,435,456 行
对照：8×A100 40GB（同数据、同 dot 交互、同每卡本地 batch；A4 档 A100 侧为 DCN v2，见脚注）

已超过同档 A100A1 134%、A2 109.7%（端到端，含 host 取数）。三点均用同数据、同 8 卡、同 dot 交互、同每卡本地 batch。

瓶颈不是算力而是「等」Cube 在矩阵乘内核里忙 91.3%，但矩阵乘只占步时 6.8%（A2）/ 13.9%（A4）；wait + 空隙占 64% / 44%，通信稳定占 25%。
整机占用天然偏低训练对齐采样 AICore 4.84%（峰值 17%）；理论占空 6.8%×91.3%≈6.2%，两者一致 —— 低占用是本负载的算术密度决定的，不是算子差。

7. 归因

7.1 已坐实

  • 查表不再是瓶颈：24 次调用（15.05 ms）→ 1 次调用（0.081 ms），统一表 + dedup 共同作用。
  • 通信稳定占 25%：每步 5 次 all2all（@A4 约 18.5 ms）+ 6 次 HcclLaunch 共 1.23 ms 纯发射开销。
  • wait + 空隙是最大单项：A2 64%、A4 44%，来自等前驱、等对端 rank、host 下发断档。
  • 算子侧无空间：Cube 91.3%、MAC 比 0.77；继续调 kernel 不会有用。
  • 带宽无空间：0.27% 占用；bf16 化实测更慢（O15 +16%）。

7.2 推测（未坐实）

  • 推测 A4 档 all2all 出现约 100 个形状特化 kernel 名，说明分块随 dedup 后唯一 id 数变化，可能触发按形状重编译/重下发；计数对齐到固定 bucket 可减 4–6 ms，需改 dynamic_emb。
  • 推测 各 rank dedup 后 id 数不均衡导致 all2all straggler，是 wait 的一部分来源；尚未取逐 rank 分布。

结论：阶段一 2× 在 A1/A2 两档不可达；若目标是「体现 950 优势」，应把验收档上移到 A4（当前 176.8%，且模型仍比 A100 侧简单）或走多机线性扩展（UB 主场）。
