## 3 数据（Kaggle DAC：45,840,617 行 / 约 4.6 GB）

```bash
# 3.1 下载（官方源不可达，走镜像；注意路径大小写）
mkdir -p <数据盘>/datasets/criteo_kaggle && cd <数据盘>/datasets/criteo_kaggle
curl -L --retry 5 -C - -o dac.tar.gz \
  "https://hf-mirror.com/datasets/Recommenders/criteo/resolve/main/dac.tar.gz"
gzip -t dac.tar.gz && tar xzf dac.tar.gz && wc -l train.txt

# 3.2 只搬 train.txt（Kaggle 路径只读这一个文件，按 7 天切分；test.txt 无标签、不用）
cp -f train.txt $PROJ/input/train.txt

# 3.3 缺失字段补 0（必改，否则预处理直接崩）
#     data_utils.py:1023  list(map(lambda x: int(x, 16) ...))  →  int(x, 16) if x.strip() else 0

# 3.4 清旧缓存（孤立 processed npz 会让程序跳过预处理，然后崩在伴生文件）
rm -f $PROJ/input/*.npz
```

**判据**：`wc -l train.txt` = **45 840 617**；`head -1 | awk -F'\t' '{print NF}'` = **40**；预处理日志 `Total number of samples: 45840617`；`ls $PROJ/input/*.npz` 至少 4 类（`kaggleAdDisplayChallenge_processed`、`train_day_count`、`train_fea_count`、`train_fea_dict_*`）。
预处理分钟到半小时级、磁盘 10 GB 量级。**不要**把 100 k 的 `dac_sample` 产物混进同一目录。

## 4 单卡冒烟（约 2 分钟）

命令同 §5，改三处：`-e ASCEND_RT_VISIBLE_DEVICES=0`、`--nproc_per_node=1`、`--stop-step 100 --test-freq 100`，日志落 `results/smoke_1d.log`。

**判据**：`NPU: set hf32 is True` → `world size: 1` → `Using 1 NPU(s)` → 有 `ms/it` 行且 loss 下降 → `EXIT=0` → 末尾有 `auc` 行。
**禁止**用 `--data-generation random` 当冒烟（必崩 `cat … 161002 dim 0 [384] vs [128]`，是数据形状不是设备问题）。

## 5 8 die 正式跑（benchmark 原配置，10240 步）

```bash
ssh <节点> "docker exec -e ASCEND_RT_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 $CTR bash -lc \"
 cd $PROJ/run && ln -sfn $PROJ/input input
 $VENV/torchrun --master_addr=localhost --master_port=6100 --nproc_per_node=8 \
  $PROJ/repos/dlrm/dlrm_s_pytorch.py \
  --arch-sparse-feature-size 16 --arch-mlp-bot 13-512-256-64-16 --arch-mlp-top 512-256-1 \
  --data-generation dataset --data-set kaggle \
  --raw-data-file ./input/train.txt --processed-data-file ./input/kaggleAdDisplayChallenge_processed.npz \
  --loss-function bce --round-targets True --learning-rate 0.1 --use-npu \
  --mini-batch-size 128 --print-freq 10 --print-time \
  --stop-step 10240 --test-freq 10240 --test-mini-batch-size 16384 --test-num-workers 16 \
  > $PROJ/results/meta_8d_10240.log 2>&1; echo EXIT=\$? >> $PROJ/results/meta_8d_10240.log\""
```

**判据**：`world size: 8` ∧ 日志到 `it 10240/…` ∧ 该点有 `auc` 行 ∧ `EXIT=0`。
`--test-freq` 必须等于 `--stop-step`：补丁的 break 在循环开头，第 10240 步的 print/test 先执行，再退出。

## 6 读数与口径

| 项 | 取法 | 禁用 |
|---|---|---|
| 精度 | 日志 `auc {:.4f}`（val/test 是同一 `train.txt` 按 7 天同源切分） | `accuracy` 行：被多数类主导，基线须现场取 |
| 吞吐 | `sps = 1024 × 1000 / ms_it`（每步全局 1024 样本），取稳态中位、剔前 10 步 | 用单卡 `ms/it` 推 8 卡；用 profiling 轮次步时当生产值 |
| 对比 | 只与本 benchmark 自身前一轮比 | 与 A100 `torchrec_dlrm` 四档相除（数据 45.8 M vs 4.19 B、d=16 vs 128） |

**判据**：1 epoch ≈ 45.84 M / 1024 ≈ **44 766 步**，`--stop-step 10240` 只覆盖 **22.9%** ⇒ 报数必须写「10240 步 / 非满 epoch」，不能写「训练完成」。表头四要素：机型 / die 数 / local batch / 步数（含是否满 epoch）。

## 7 失败对照（按序排查，不要改参数试）

| 现象 | 根因 | 处置 |
|---|---|---|
| `environment variable MASTER_ADDR expected` | 裸 `python` 起，脚本无条件走 extend_distributed | 必须 `torchrun` |
| 子进程 `exitcode 2`，日志 `error: expected one argument` | `--num-indices-per-lookup-fixed` 要取值；`--test-num-batches` 不存在 | 加取值；测频用 `--test-freq` |
| `OverflowError: Python integer … out of bounds for int32` | Kaggle 哈希是 uint32，约一半超 int32 | 用带 `int64` 的补丁并清空旧 npz；不要用 `--max-ind-range` 压哈希空间绕过 |
| `could not broadcast input array from shape (23,) into shape (26,)` | 空字段被丢掉，26 列退化 23 列 | §3.3 空字段补 0 |
| `FileNotFoundError: ./input/train_day_count.npz` | input/ 里只有别人留的孤立 processed npz | 删掉全部 npz，让程序按 `--raw-data-file` 重新生成 |
| `cat … 161002 dim 0 [384] vs [128]` | `--data-generation random` 的变长 lookup 与 `torch.cat` 不符 | 改用真实数据 + `--stop-step` |
| `Data set option is not supported` | `--data-set` 只收 `kaggle` / `terabyte` | 改 `kaggle` |
| 精度异常 | `MODEL_HF32_FLAG` 默认 TRUE（日志 `set hf32 is True`）、`MODEL_EPOCH` 会覆盖 `--nepochs` | 精度对照显式 `MODEL_HF32_FLAG=FALSE`，并核 env 未被串改 |
